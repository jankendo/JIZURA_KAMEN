# JIZURA Custom Edition 1.3.0 — 添付動画監査と単一背景への改修

基準：公開 v38（1.2.1）、commit `4ea862dc298d02100625bbe6a6a9a11e4a555156`。
対象：オオサカスタイル(6).mp4 と JIZURA_DIRECTOR_PACK(2).zip。

## 判定

添付動画を「最高品質・最適な演出」とは判定しません。主テロップの可読性、クレジット、内部座標表示、同一画像の重複登録、指定された縦書き上昇演出に具体的な改善点があります。修正はアプリへ適用しました。提出済みMP4の画素を後から変更したものではありません。

映像の迫力、歌唱との知覚的同期、楽曲に対する物語の最適性は、数値の満点だけでは保証できません。歌詞やLRC時刻を推測で書き換えず、画質・音質・解像度・FPS・ビットレートを下げる対応も行っていません。

## 発見した問題・原因・修正

| 問題 | 原因 | 改修 |
|---|---|---|
| 同じ画像が3素材として扱われる | 画像選択が置き換えではなくvisualAssetsへの追記 | 背景1枚の選択・置き換えへ統一。ドラッグ＆ドロップも先頭1枚だけ。複数画像一覧・固定・役割・SNS画像選択を廃止 |
| 旧追加画像が意図せず混ざる | 保存された素材群が再計画の候補になる | 編集アプリの計画・Director Packを単一背景の実効データへ統一。保存プロジェクト内の旧画像、scenePins、旧追加画像は保全し、使用しない |
| 主テロップが写真に埋もれる | mainDraw→drawFx経路がenv.drawの可読性補正を通らない | 主テロップにも同じ補正を接続。写真上の塗り文字に対比色の縁取り・影を付け、追加された輪郭を安全領域の計算にも含める |
| 黄色の画面で白い文字が低コントラスト | 文字色の補正を文字単位のアニメーション色が上書き | グラフィック背景と文字の明暗を比較し、文字単位の色にも反映。outline、ghost、色板の設計は保持 |
| 完成映像にX494 Y406 | crosshair装飾が内部座標を通常テキストとして出力 | 生成元にdebug属性を付ける。通常プレビュー・本番描画で抑止。利用者の歌詞に座標やLINEが含まれる場合は本文を保持 |
| クレジットが暗く小さい | コントラスト補正後、scene-awareの透明度0.28、サイズ0.52倍で再度弱める | 読みやすい透明度0.85・サイズ0.68倍へ。主テロップと競合するクライマックス等では既存の非表示判断を維持 |
| 縦書きriseがほぼ動かない | 全高に近い文字列が安全領域へ毎フレーム戻される | 上昇・下降の移動余白を確保し、移動に沿った安全な窓で配置。明示ロックは尊重 |
| 元画像を再圧縮する | 入力時に4096pxへ縮小し、WebP品質0.9へ変換 | 新規入力は検証済みの元バイトを保存。形式は既存対応のJPEG/PNG/WebP。6400万画素を超える画像は縮小せず明示的に拒否 |
| 元解像度より小さい描画 | 素材デッキの2048px上限の画像で主背景を置き換える | 単一背景の描画では元解像度の背景を使用。既存のデッキ上限は互換用の素材解析に残す |
| 手動ズーム・位置が二重適用されうる | 新しい単一背景候補に背景設定と同じcropを複製する | 素材側のcropは中立。背景の手動設定は一度だけ適用し、既存のシーン・カメラ演出を維持 |
| 別処理中に背景を置き換える競合 | 入力ハンドラが演出生成・配色解析の実行中を判定しない | 生成・解析中の置き換えを拒否。壊れた画像はプロジェクトへ適用する前に検証 |
| 計画生成が保存設定を変更する | 旧プランナーがartDirection.vocabularyを参照経由で更新 | 小さな演出メタデータだけ分離。画像や音声の巨大データを複製しない |

補助動画の既存機能はMP4/WebM専用入力として保持しました。そこからも画像を追加することはできません。追加画像・ロゴを含む旧データはバックアップに残りますが、今回の単一背景モードでは描画しません。

## 可読性の数値

`#E9AA31` のフィールドと白のコントラスト比は約 **2.05:1**、修正後の `#10151e` は約 **8.94:1**。これは指定色から計算した値であり、動画の全フレームの最小コントラスト比を測定した値ではありません。実Canvasによる色の適用・文字単位の色・安全領域を検査しました。

背景1254×1254は、16:9 1080pの基本cover配置で約1.53倍の拡大になります。拡大や高ビットレート化だけでは細部は増えません。元画像・出力サイズ・基本配置の拡大倍率を画面へ表示します。720pの設定を勝手に1080pへ変更せず、利用者の出力設定を維持します。

## 検証と限界

- 49のJavaScriptモジュール構文検査、ビルド、差分の空白検査。
- エンジン回帰140件中138件成功、0件失敗、ブラウザ依存2件未実施。隔離コピーからnpm ci→テスト→buildも検証。
- 単一背景、置き換え、旧素材保全、プロジェクト移行、手動crop、補助動画保持、内部表示抑止、歌詞本文保持、文字コントラスト、縦書きの移動・安全領域、元画像のバイト保持を追加検査。
- 実際の背景入力ハンドラを隔離アダプターで実行し、破損入力で旧プロジェクトが変わらないこと、複数ドロップで追加画像が蓄積しないこと、生成中の入力が拒否されることを確認。
- 添付素材を使った再構成テストで、25行すべてに歌詞画素が存在すること、本文・LRC開始時刻、各アスペクト比の出力設定が変わらないことを確認。
- Landscape / Vertical / Square各2秒・1080p・30fps・H.264/AAC 48kHz 192kbpsの検証MP4を、実アプリのCanvas描画→FFmpegで生成し、MP4のトラック・フレーム数・音声・再デコード画素を検証。
- 音声解析のソースとエンコーダーのソースはv38から変更なし。保存用DB名・object store・schema version・localStorage keyを変更せず、データの削除・初期化・移行を行わない。

ブラウザ操作用の指定環境がないため、実ブラウザのアップロード導線・WebCodecs書き出し・可変フォント軸・Consoleは未検証です。FFmpeg検証をブラウザ書き出しの成功とは扱いません。

完全な元プロジェクトJSONは添付されていません。再構成した素材テストは元の編集状態の厳密な再現ではありません。歌唱を聴いた知覚的同期は確認できておらず、LRCを自動で補正しません。PackのsemanticDirection 79 / beatSync 67 / lyricSync 81等は内部の参考指標であり、歌唱との同期・美的品質の確定値ではありません。指標を満点に書き換えず、未測定項目を成功に見せる対応も行っていません。

## 保存データ・公開

1.3.0は新しい保存版として公開する対象です。v38とv35のソース・保存アーカイブは保持します。Site名・URL・共有設定・Secrets・環境変数を変更しません。今回の改修を戻す場合は保存済みv38を再デプロイできます。履歴番号とデプロイ結果は完了メッセージで報告します。

## 残る確認項目

1. 利用者のブラウザで同じプロジェクトを開き、全25行の歌唱に対する表示開始・終了を聴いて確認する。
2. 1080p以上を求める場合、より高解像度の原画を使用する。既に圧縮された保存画像の細部は修復できない。
3. 複数画像時代の素材は背景1枚へ切り替わるため、旧シーンの画像固定・追加ロゴ等が表示されないことを確認する。
4. 元プロジェクトを使い、ブラウザ上で全編MP4を生成して最終視聴する。演出の評価を内部の満点だけで済ませない。
